# ADR 0005: Builds leave the working tree clean

- Status: Accepted
- Date: 2026-10-14

## Context

`pnpm build` produces two kinds of output inside the repository:

- The GitHub Action bundle, `action/dist/index.js`, which is committed because the Action runs straight from the repository.
- Feeds generated by `shipdot build` for the docs site and the examples (`shipdot.json`, `llms.txt`, `llms-full.txt`, copied assets). `shipdot.json` carries `generatedAt`, so it changes on every build.

When a build modifies a tracked file, `pnpm publish` refuses to run (`ERR_PNPM_GIT_UNCLEAN`) and the CI check on `action/dist` fails. The v0.1.0 release hit exactly this: the version bump changed `packages/cli/package.json`, whose `version` is inlined into the Action bundle, but the bundle was not rebuilt. Separately, the bundle embedded `//#region ../node_modules/.pnpm/<pkg>@<version>/...` comments, whose paths depend on the local pnpm store layout (virtual store directory names, which pnpm can shorten with a hash depending on settings and platform), so it was not guaranteed to be byte-identical across machines.

## Decision

- **The Action bundle is committed and reproducible.** It is built without debug region comments (`attachDebugInfo: 'none'` in `action/tsdown.config.ts`), so it contains no file system paths and is byte-identical on Linux, macOS and Windows. `pnpm version-packages` rebuilds it, so a version bump and its bundle land in the same commit.
- **Generated feeds are build output and are gitignored**, not made deterministic. They are derived from `.shipdot/entries/`, which is the source of truth ([ADR 0001](0001-git-as-source-of-truth.md)); committing them would duplicate it. `generatedAt` is required by the v1 feed format ([ADR 0004](0004-feed-format-v1.md)) and should state when the feed was really built. Faking it (for example with the newest entry date) to get stable bytes would make it lie.
- **CI enforces both**: after `pnpm build`, on Ubuntu and Windows, `git status --porcelain` must be empty.

## Consequences

- Positive: `pnpm build && pnpm publish` works on any OS, and the clean-tree check catches stale bundles and new unignored output in the pull request that introduces them.
- Positive: diffs of `action/dist` only change when the bundled code changes.
- Negative: the bundle has no region comments pointing at source files; use the sources in `action/src` and `packages/*/src` to debug it.
- Negative: any new generated file must be added to `.gitignore`, or CI fails.
